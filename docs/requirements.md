# チューリング・パターン体験アプリ 要件定義書（MVP）

本書は初期MVPと追加実装の現状を記載する。将来候補・性能目標・未実装課題は実装済み機能と区別する。2026-10-06時点でGitHub `main` とローカルの基準コミットは `9662eab19b048ba5785285b09259ed3b314e6d50` で一致していた。

## 1. 概要

### 1.1 アプリ名

Turing Pattern Lab

### 1.2 目的

チューリング・パターン（反応拡散系）によって生成される自然界の模様を、ユーザーが視覚的かつ直感的に体験できるWebアプリを提供する。

教育用途、サイエンスアート用途、数学への興味喚起を主目的とする。

### 1.3 対象ユーザー

- 数学や自然科学に関心がある一般ユーザー
- プログラミング学習者
- 学生
- 教育関係者
- サイエンスアート愛好家
- 生成アートに関心があるユーザー

## 2. MVP方針

MVPでは「まず触って楽しい」ことを重視する。

数式の詳細説明や高度なパラメータ調整機能は後続フェーズとし、初期版では視覚的な体験価値を優先する。

## 3. システム構成

### 3.1 フロントエンド

- React
- TypeScript
- Vite

### 3.2 描画

- HTML Canvas

MVPではCanvasを採用する。WebGL対応は将来拡張とする。

反応拡散の描画はCanvas 2Dで行う。追加の顔入力には `@mediapipe/tasks-vision` のFace Landmarkerを使用し、その推論ではGPU delegateを指定する。

### 3.3 バックエンド

- なし
- 完全クライアントサイドアプリ

## 4. 主要機能

## F-01 パターン生成

### 概要

チューリング・パターンをリアルタイム生成する。

### 要件

- 初期表示時に自動生成を開始する
- 初期プリセットはZebraとする
- Canvas上にパターンを描画する
- アニメーションとして時間発展を表示する
- MVPではGray-Scottモデルを採用する

## F-02 プリセット選択

### 概要

代表的な模様をワンタップで切り替えられるようにする。

### プリセット例

- Zebra：シマウマ風のストライプ
- Giraffe：キリン風の網目模様
- Leopard：ヒョウ柄風のスポット
- Coral：サンゴ風の有機的模様
- Maze：迷路風のパターン

### 要件

- プリセット名を表示する
- 選択すると即座にパラメータが反映される
- 選択時にパラメータとSeedを適用し、シミュレーションを初期化する
- Built-inとSavedのグループに分けて表示する
- Built-inは現在の色とScaleを維持する。Savedは保存されている色とScaleを復元し、旧形式で省略された項目は現在値を維持する
- MVPではサムネイル画像は必須としない

## F-03 パラメータ調整

### 概要

模様の変化を体験できるよう、主要パラメータを調整可能にする。

### MVP対象項目

- Feed
- Kill
- Seed（初期配置パターン）

### 将来候補

- Diffusion A
- Diffusion B
- Iteration speed
- Noise amount

### UI

- スライダーで調整する
- 現在値を数値表示する
- Feed / Kill は微調整ボタンで0.0001単位の増減ができる
- Feedは0.0120〜0.0700、Killは0.0450〜0.0720、スライダーも0.0001刻みとする。範囲外の調整値は上下限へ制限する
- Feed / Killの変更は現在の化学物質分布を維持し、プリセット選択表示をCurrent settingsへ切り替える
- Seedは選択式とし、変更時は現在のFeed / Killを維持したまま初期状態から再開する
- SeedはCenter / Stripe / Spots / Web / Noiseの初期配置を表す。再現用の数値乱数シードではなく、同じ設定でもランダム配置が変わることがある

## F-04 ランダム生成

### 概要

ランダムなパラメータを生成し、予期しない模様との出会いを提供する。

### 要件

- Randomボタンを配置する
- クリックするとFeed/Killなどの値をランダム設定する
- 再生成時は初期状態もリセットする
- RandomはFeed / KillとSeed（Center / Stripe / Spots / Webから選択）を変更し、現在の色とScaleは維持する
- 小さい検証用シミュレーションで初期の活動性を確認し、候補が見つからない場合は安定候補を使う。長時間の活動性は保証しない
- Restartは現在のパラメータとSeedで初期配置を作り直し、色とScaleを維持する
- Random / Restart / プリセット・Seed変更はユーザーのPause状態を変更しない

## F-05 一時停止／再開

### 概要

アニメーションを停止・再開できるようにする。

### 要件

- Pause / Resume を切り替えられる
- 停止中も現在のパターンは表示維持する
- Pauseは反応拡散の計算ステップを止める。Canvasへの描き込み、色変更、有効な音声・モーション・顔イベントの刺激は停止中も反映される
- 目の閉眼による停止はユーザーのPause状態と独立する。開眼してもユーザーがPause中なら時間発展は再開しない

## F-06 画像保存

### 概要

生成したパターンを画像として保存できるようにする。

### 要件

- PNG形式で保存する
- Canvas内容をエクスポートする
- ファイル名は `turing-pattern.png` とする
- 選択中の色・攪拌を含む現在のCanvas内部解像度で保存し、UIやカメラ映像は含めない

## F-07 ミニ解説

### 概要

チューリング・パターンの概要を短く説明する。

### 表示内容

- チューリング・パターンとは何か
- なぜ模様が生まれるのか
- 自然界の例

### MVP要件

- 固定テキストでよい
- 詳細な数式解説は必須としない

## F-08 カスタムプリセット保存

### 概要

Randomやスライダー調整後の現在設定を、ユーザーが再利用できるプリセットとして保存する。

### 要件

- 現在のFeed / Kill / Diffusion A・B / Seed / 背景色・物質色 / Scaleを保存する
- 保存名をユーザーが指定できる
- 保存済みプリセットをプリセット選択に表示する
- 保存済みプリセットを削除できる
- MVPではブラウザのlocalStorageに保存する
- キーは `turing-pattern-lab:user-presets:v1`、永続化は有効な最新30件までとする。セッション中の一覧には30件を超えて表示されることがある
- 保存名は前後の空白を除去し、連続空白をまとめ、40文字までとする。保存名入力のキャンセルは保存せず、空入力は既定名を使う
- 削除は選択中のユーザープリセットのみを対象に確認を表示し、現在のパターンは変更しない
- 現在の化学物質分布・乱数状態・Pause・Fullscreen・センサー有効状態や感度・権限は保存しない
- 色やScaleを含まない旧プリセットは読み込み可能とし、不正なJSONや不正なプリセットは読み込み対象から除外する
- localStorageが利用不可または容量不足でもシミュレーションを継続する。現状は保存失敗をUIに通知しないため、再読み込み後の保持は保証されない
- 保存先は同一ブラウザ・同一オリジンに限定し、サイトデータ削除で失われる。クラウド同期やプリセットの入出力は未実装とする

## F-09 Canvasジェスチャー注入

### 概要

Canvasをタップまたはドラッグした地点に促進物質を注入し、ユーザーが現在のパターンを局所的にかき乱せるようにする。

### 要件

- タップ地点に促進物質を注入する
- ドラッグした線に沿って連続的に促進物質を注入する
- Feed / Kill の値は変更しない
- 通常表示、Fullscreen、スマートフォン向けCanvasビューで同じ操作ができる
- Fullscreen / Canvasビューの挙動はF-15に記載する
- ブラシ半径は100%スケール時に初期実装の約80%とし、Canvas内部解像度スケールが大きいほど表示上は小さくなる

## F-10 スマートフォンモーション攪拌

### 概要

スマートフォンで対応ブラウザを使用している場合、端末のモーションセンサー入力に合わせてCanvas内部の反応拡散状態を一時的に攪拌し、パターンの動きそのものが揺さぶられる感覚を追加する。

### 要件

- スマートフォン幅または粗いポインター環境でのみ操作を表示する
- 表示条件は `(max-width: 820px), (pointer: coarse)` かつDeviceMotionEvent対応とする
- ユーザー操作後にモーションセンサーの使用を開始する
- センサー未対応または許可拒否時は通常のCanvas操作を維持する
- Canvas要素自体はCSS transformで揺らさない
- Canvas内部のシミュレーション状態を変化させ、PNG保存には攪拌後の状態が反映される
- 攪拌量は上限を設け、画面操作を妨げない範囲に抑える
- 感度を50%-200%で10%刻みに調整でき、初期値は100%とする
- 100%は現在のPhone motion反応と同じ強さとする

## F-11 カラーパレット調整

### 概要

Canvas内の背景色と物質色をユーザーが選択できるようにし、現在の標準表示色へ戻せるReset操作を提供する。

### 要件

- 背景色と物質色を個別に選択できる
- 初期値は現在の表示色である背景 `#e6b01a`、物質 `#2edeef` とする
- Reset Colorsで初期値へ戻せる
- 色変更はシミュレーション状態をリセットしない
- PNG保存には選択中の色を反映する

## F-12 音声入力攪拌

### 概要

マイク入力の音量と低音／中音／高音域の解析値を使い、Canvas内部の状態を攪拌する。

### 要件

- 表示条件は `(max-width: 820px), (pointer: coarse)` かつAudioContext・getUserMedia対応とする
- Enable Audio操作でマイク権限を要求し、Stop Audioでマイクトラック、解析ノード、AudioContext、サンプリング用アニメーションフレームを解放する
- 状態表示はReady / Active / Blocked / Stoppedとし、開始失敗や権限拒否時も通常シミュレーションを使用できる
- 音量と帯域別エネルギーにより内部状態を変化させ、中音域は計算に渡すFeed / Killを一時変調する。スライダーの設定値は変更しない
- 感度は50%-200%で10%刻み、初期値100%とする
- `visibilitychange`で非表示になった時、または`pagehide`で停止する。復帰後は手動で再有効化する
- マイクの記録・送信・永続化は行わない

## F-13 顔・視線・瞬き入力

### 概要

Start Camera / Stop Cameraから任意で顔入力を開始・停止する。手動キャリブレーションなしで顔の向きと虹彩移動を組み合わせ、上下左右・中央の5方向へ瞬き時の刺激を与える。

### 実装済みの挙動

- デスクトップ・モバイル共通のEye interactionパネルを表示する
- 前面カメラ、1人の顔、Face LandmarkerのVIDEOモードを使用する
- 自動基準値収集と時間平滑化・方向保持を行う
- 両眼閉眼係数の平均が0.55を超える時に閉眼とし、開眼時に通常刺激を1回発火する
- 閉眼が1200ms以上なら開眼時に強い刺激を1回発火する。継続注入や左右別ウインク判定は行わない
- 閉眼中は反応拡散の時間発展を止める。センサー等の攪拌処理は継続する
- 非表示videoで処理し、カメラ映像・ランドマークを保存・送信しない
- 開始失敗時はエラーを表示し、取得済みリソースを解放する。正常な停止・コンポーネント解除でもリソースを解放する

モデル・WASMは外部配信元から読み込むため、カメラ開始にはネットワーク接続が必要。現状ではカメラのバックグラウンド停止、開始中のキャンセル、停止・顔消失時の閉眼解除などが未実装である。構成・判定値・未実装課題・テスト範囲は[顔入力設計](face-interaction-design.md)を参照する。

## F-14 内部解像度Scale

### 要件

- 50%-200%を10%刻みで調整し、初期値を100%とする
- 通常表示の基準サイズは224×224セルとし、50%は112×112、200%は448×448とする
- 表示上のズームではなく、内部の計算セル数とPNGの画素数を変更する
- 解像度が変わると現在のSeed・パラメータで初期化し、現在の化学物質分布は保持しない
- Fullscreen / Canvasビューでは表示領域の縦横比に合わせて基準サイズを計算してからScaleを適用する
- 高いScaleほど計算負荷が増える。自動負荷調整は未実装とする

## F-15 Fullscreen / Canvasビュー

### 要件

- 対応環境ではCanvas stage全体をFullscreen APIの対象とし、CanvasとExit操作を同じ領域に含める
- Fullscreen APIが非対応または拒否された場合は、アプリ内のCanvasビューへフォールバックする。フォールバック自体はスマートフォン専用ではない
- 描画領域をsafe area／ディスプレイカットアウトの背面まで広げ、Exitなどの操作UIをsafe area内に配置する
- Exitで通常表示へ戻る。CanvasビューはEscapeキーでも終了できる
- 表示領域の寸法変更・表示モード切替により内部解像度が変わった場合は、パターンを初期化する

## 6. 非機能要件

## 6.1 パフォーマンス

- PCでは60fpsを目標とする
- スマートフォンでは30fps以上を目標とする
- 端末性能に応じてCanvas解像度や計算ステップを調整できる設計とする

上記fpsは設計目標であり実測保証ではない。現状はメインスレッド上で`requestAnimationFrame`ごとに3ステップを計算し、Scaleのみ手動調整できる。計算速度UI・Worker化・負荷やfpsに応じた自動調整は未実装とする。

## 6.2 対応ブラウザ

最新版の以下ブラウザを対象とする。

- Chrome
- Safari
- Edge

上記は対象環境であり、全機能のクロスブラウザー実証を意味しない。カメラ・マイクにはHTTPSまたはlocalhost等のsecure contextが必要で、権限・端末センサー・GPU推論対応により任意入力の可否が変わる。カメラ開始時はGoogle storageのモデルとjsDelivrのWASM取得が必要。外部配信障害やオフライン時のローカルモデルフォールバックは未実装とする。

## 6.3 アクセシビリティ

- ボタンやスライダーには適切なラベルを付与する
- 色だけに依存しないUIにする
- キーボード操作に極端に弱い実装を避ける

## 6.4 プライバシー・端末リソース

- Audio noiseはマイク音声そのものを保存せず、音量と低音／中音／高音の解析値のみをCanvas反映に使う
- Audio noiseのON/OFF、マイク権限状態、感度はローカルプリセットに保存しない
- Audio noiseが有効な状態でアプリがバックグラウンドに入った場合、マイクトラックを停止して自動再開しない
- カメラ映像・ランドマークを保存・送信しない。カメラ状態と基準値は永続化しない
- カメラのバックグラウンド時リソース解放は未実装課題であり、Audio noiseと同じ保証はない

## 6.5 デプロイ

- Vercelでのデプロイを想定する
- 静的Webアプリとして配信可能な構成にする
- アイコンとweb manifestは配置済み。Service Workerやオフラインキャッシュは未実装とする
